# 쿼리 전략 비교

## v1. 셀 단위 COUNT 방식

- 각 셀마다 COUNT 쿼리 실행
- 최대 SQL 실행 수: 64회
- 장점: 구현이 단순하고 셀의 의미가 명확함
- 단점: 셀이 늘어날수록 SQL 실행 수 증가

## v2. 행 단위 집계 방식

- 통계표의 한 행을 하나의 집계 단위로 조회
- 최대 SQL 실행 수: 8회
- 장점: 기존 통계표의 행 기준을 유지하면서 호출 수를 크게 줄일 수 있음
- 단점: 행 수만큼 SQL이 실행되며, 행별 집계 로직이 반복될 수 있음

## v3. 전체 단일 집계 쿼리 방식

- GROUP BY와 SUM(CASE WHEN ...)으로 전체 통계표 조회
- SQL 실행 수: 1회
- 장점: DB round-trip 최소화
- 단점: SQL이 복잡해지고 통계 규칙이 한 쿼리에 집중됨

## 선택 기준

v3가 항상 정답은 아니다.  
통계 컬럼이 고정되어 있고 조회 조건이 단순하면 v3가 유리할 수 있지만, 상태나 분류가 자주 바뀌거나 운영자가 SQL을 직접 확인해야 하는 환경에서는 v2나 목적별 다중 집계 쿼리가 더 나을 수 있다.
